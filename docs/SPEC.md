Принято: путь B (веб), название рабочее — оставлю `paint-by-numbers`. Ниже — полная инструкция от пустой папки до работающего приложения на iPad. Её же можно целиком положить в `SPEC.md` в корне репозитория и ссылаться на неё в Cursor.

> **ОБНОВЛЕНИЕ v3 (сентябрь 2026).** Экран выбора сложности УДАЛЁН. Конвейер — «умная» автоконвертация: даунскейл ≤1400 px → **guided filter** (edge-preserving, `smooth.ts`) → **SLIC**-суперпиксели K≈пиксели/350 (2000–5000, m=10, `slic.ts`) → k-means по средним суперпикселей с **авто-k по SSE-elbow** (k∈[10..36], раздел 4 плана) → перцептивное уточнение палитры (`autoPalette.ts`: дедуп ΔE<5 + агломеративное слияние до 36 символов 1–9,0,A–Z) → RAG-слияние мелких регионов → majority-фильтр 3×3 → **векторные контуры** (`vectorize.ts`: ориентированная трассировка границ → Douglas–Peucker ε≈1.2 → Chaikin ×2 → `Path2D` с round join) → номера по max-удалению от границы. Символы легенды — `symbols.ts` (`symbolFor`). Экспорт дописывает чёрную полосу-легенду как у реальных наборов. Проверка качества: диагональная граница после DP — прямая линия (тест `v3pipeline.test.ts`), отклонение ≤1 px.

## Шаг 3. Данные и константы (единый источник правды)

**Пресеты сложности** (константы, тюнинг позже):

| Пресет | k (цветов) | minArea (% рабочих пикселей) |
|---|---|---|
| Лёгкий | 10 | 1.2% |
| Средний (рекомендация) | 18 | 0.4% |
| Сложный | 32 | 0.1% |
| Максимум | 45 | 0.03% |

Пример расчёта: рабочее изображение 1400×1400 = 1 960 000 пикселей. Лёгкий уровень: 1 960 000 × 0.012 ≈ 23 500 пикселей — регионы меньше этой площади сливаются с соседями.

**Динамические границы:** `kMax_eff = min(45, floor(pixels/2000))`, но не меньше 8. Обоснование: при максимуме средняя область должна быть ≥ ~2000 пикселей, иначе регионы вырождаются. Ползунок: `[8; kMax_eff]`. Рекомендация = пресет «Средний».

**Рабочее разрешение:** длинная сторона ≤ 1400 px для конвертации; итоговые канвасы ≤ 2048×2048 (лимиты Safari на размер canvas сверить в документации Apple; 2048 — безопасный запас).

### Задание 4. `colorSpace.ts` + тесты
Преобразования `rgbToLab`, `labToRgb`, `labDistance` (стандартные формулы, проверяемые):

```
// sRGB(0..255) → линейный
c = c/255; c <= 0.04045 ? c/12.92 : ((c+0.055)/1.055)^2.4
// линейный RGB → XYZ (D65)
X = 0.4124564R + 0.3575761G + 0.1804375B
Y = 0.2126729R + 0.7151522G + 0.0721750B
Z = 0.0193339R + 0.1191920G + 0.9503041B
// XYZ → Lab, белый D65: Xn=0.95047, Yn=1.0, Zn=1.08883
f(t) = t > 0.008856 ? t^(1/3) : 7.787t + 16/116
L = 116·f(Y/Yn) − 16; a = 500·(f(X/Xn) − f(Y/Yn)); b = 200·(f(Y/Yn) − f(Z/Zn))
```

Тесты (эталонные значения — стандартные справочные): белый → L=100, a=0, b=0; чёрный → 0,0,0; красный (255,0,0) → L≈53.23, a≈80.11, b≈67.22 (допуск ±0.5); раундтрип `rgb→lab→rgb` с точностью ±1 на градацию. Запуск: `npx vitest run`.

### Задание 5. `quantize.ts` + тесты
K-means++ в пространстве Lab:
- инициализация: первый центроид случайно (с фиксированным seed), каждый следующий — с вероятностью, пропорциональной квадрату расстояния до ближайшего уже выбранного;
- итерации: присвоение ближайшего центроида (по `labDistance`), пересчёт центроидов как среднее; стоп при стабилизации или 20 итераций;
- вход: массив пикселей (Lab), выход: палитра `[{index, lab, hex, pixelCount}]` и карта меток `Uint16Array`.

Тесты: синтетическое изображение из 3 чистых цветов при k=3 даёт ровно эти 3 цвета (допуск по Lab ≤ 5); детерминированность при одинаковом seed.

### Задание 6. `segment.ts` + тесты
1. Связные области по карте меток: BFS, 4-связность. Регион: `{colorIdx, area, pixels, bbox, соседние регионы}`. Соседство определяется по парам пикселей с разными метками, стоящих рядом.
2. Слияние: пока есть регион с `area < minAreaPixels` — объединить с соседом, ближайшим по расстоянию Lab; площадь и соседства пересчитываются.

Тесты: картинка 10×10 с квадратом 2×2 другого цвета при большом `minArea` сливается с фоном; при `minArea=0` остаётся отдельным регионом.

### Задание 7. Контуры и номера (`contour.ts`, `labels.ts`)
- Контур: пиксель границы там, где метка отличается от правой или нижней соседней; рисовать чёрным, толщина 2 px на рабочем разрешении.
- Номер региона: точка, максимально удалённая от границы региона (обратный BFS от границ региона → пиксель с максимальной дистанцией); запасной вариант — центроид, если внутри.
- Размер шрифта номера — эвристика: `clamp(round(sqrt(area)/3), 10, 48)` px; цифра тёмно-серая (#333). Это стартовые константы, тюнинг позже.
- Выход конвейера: `{width, height, labels (типизированный массив), palette, regions: [{colorIdx, area, labelX, labelY, fontSize}]}`.

### Задание 8. `pipeline.ts` + Web Worker + экран обработки
- Воркер создаётся так: `new Worker(new URL('./worker.ts', import.meta.url), { type: 'module' })`.
- Шаги конвейера в воркере: даунскейл → квантование → регионы → слияние → контуры → номера.
- Прогресс: сообщения `{type:'progress', step, percent}` с диапазонами: даунскейл 0–5%, палитра 5–55%, регионы 55–70%, слияние 70–85%, контуры 85–95%, номера 95–100% (диапазоны приблизительные, только для отображение).
- `ProcessingScreen`: прогресс-бар и название шага (строки через i18n), обработка ошибок с возвратом на Home.
- Тяжёлые массивы передавать через `transfer` (transferable objects).

### Задание 9. Экран сложности
Три карточки пресетов + ползунок `[8; kMax_eff]` + бейдж «Рекомендовано» на среднем. Предпросмотры: последовательно прогнать конвейер для трёх пресетов, показывать спиннер на каждой карточке. Выбор пресета или точного k ползунком → сохраняет `{k, minArea}` → переход к раскрашиванию.

Контуры рисуются из `labels` (проход по пикселям, чёрные границы) и номеров из `regions` на канвас слоя 2. ### Задание 11. Кисть и ластик (`BrushEngine.ts`)

## Фаза 2 (сентябрь 2026, из конкурентного анализа Happy Color / Pigment)

Позиционирование: **«качество генерации из личного фото + механика реальной картины кистью»** — ниша между Happy Color (каталог, tap-to-fill) и Pigment (кисти, подписка). Конкурентное УТП — качество границ (guided filter + векторное сглаживание против полигональных границ конкурентов).

**Реализовано:**
1. **Подсветка регионов активного цвета** (из Happy Color). Отдельный слой-канвас между контурами и краской; регионы выбранного `colorIdx` тонированы цветом палитры (α≈0.35). Слой под краской: закрашенные области сами скрывают подсветку → видны только незакрашенные места; ластик «возвращает» подсветку. Перерисовка только при смене цвета (`regionIdsByColorIndex`, кэш путей).
2. **«Закончить за меня»** с диалогом подтверждения (из Happy Color). Запись истории `{tool:'fill-all'}`: offscreen-канвас эталонной заливки → `destination-over` на канвас краски → заливаются только прозрачные (нераскрашенные) пиксели, мазки пользователя остаются поверх. Участвует в undo/redo и сериализуется в проект. Ядро — `engine/fillRender.ts` (`buildFillPixels`: безшовная по-pixel заливка).
3. **Дев-кнопка «эталонная заливка»** (кнопка тестирования): видна только в dev-сборке или с `?dev=1`. Верхний оверлей-канвас (`pointer-events:none`) показывает полностью раскрашенную картину: цвета регионов + чёрные контуры, номера скрыты под краской.

**Отложено (фаза 2+):** автолупа у края холста при сильном зуме.

**Не делаем в MVP (зафиксировано):** tap-to-fill-механику (не наш жанр — у нас кисть), рекламу (ломает медитативность), лицензионный контент (юридическая нагрузка не для старта).
